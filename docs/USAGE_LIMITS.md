# 어떤 한도를 확인하나요?

자동 안내도 추가했습니다. 정기 실행에서 처리량이 커지면 Telegram으로 대기 영상 수·알려진 영상 길이·길이 미확인 수·예정 요약 글자 수·이 프로그램의 예산 예약 비율을 보냅니다. 기준은 70% 사용, 대기 영상 10개, 확인된 대기 길이 3시간, 요약 12,000자입니다. 90% 또는 부하 기준 2배에 도달하면 한 단계 높은 안내를 하루 한 번 더 보냅니다. 같은 단계 안내는 재실행해도 중복 전송하지 않습니다. 채널을 줄이려면 Codex 대화에서 제외할 채널명을 알려주세요. Telegram 봇이 답장을 받아 채널을 직접 변경하는 기능은 없습니다. 한도 계산·알림에는 AI를 호출하지 않습니다. 서비스 전체의 실시간 잔여량을 조회하는 기능이 아니라 프로그램 장부 기반의 사전 안내이므로 다른 앱의 사용이나 길이 미확인 영상은 정확히 예측할 수 없습니다.

이 대화에서 코딩·수정·진단을 요청하면 Codex의 5시간·주간 사용 한도를 사용합니다. 배포된 GitHub Actions 프로그램은 Gemini API만 호출하며 OpenAI 모델을 호출하지 않습니다. 자동 감시 채널 수를 늘려도 그 정기 실행이 Codex 사용 한도를 소비하지는 않습니다.

자동 요약에는 별도의 Gemini 무료 요청 수, 분당 입력 토큰, YouTube 영상 처리 시간 제한이 적용됩니다. [AI Studio 사용량](https://aistudio.google.com/usage)에서 **현재 API 키와 연결한 프로젝트**를 선택해 확인하세요. [공식 한도 설명](https://ai.google.dev/gemini-api/docs/rate-limits)에 따르면 한도는 API 키별이 아닌 프로젝트별이며 일일 요청은 미국 태평양 자정에 초기화됩니다.

운영 확인 기록 기준 값은 RPM 5, TPM 250,000, RPD 20입니다. 실제 서비스의 현재 한도와 이용 가능량은 AI Studio가 우선입니다. 별도로 프로그램 자체의 일일 토큰 예약 예산은 1,000,000이며, 이것을 Google이 제공하는 일일 무료 토큰 수로 해석하면 안 됩니다. 실패·테스트·토큰 계산 요청도 프로그램 장부에 보수적으로 포함하므로 요청 20회가 영상 20개를 뜻하지 않습니다. 장부는 이 프로그램의 예약 기록이며 다른 앱의 같은 프로젝트 사용까지 포함하지 않습니다. 실제 API 429에서도 처리 대기하며 유료 모델로 전환하지 않습니다.

[공식 영상 문서](https://ai.google.dev/gemini-api/docs/video-understanding)는 무료 YouTube 입력에 하루 8시간 제한을 명시합니다. 프로그램은 초기화 시각의 불명확성을 고려해 최근 24시간 기준으로 제한하고, 영상 토큰 계산과 요약 생성의 길이를 각각 예약합니다. 따라서 실제 요약 가능한 원본 영상 시간은 8시간보다 적을 수 있습니다.

채널 목록을 확인하는 RSS 조회 자체는 Gemini 토큰을 사용하지 않습니다. 새 영상의 수·길이와 재시도 횟수가 AI 사용량에 영향을 줍니다. 무료 처리량을 초과하면 남은 영상을 저장해 다음 기회에 처리합니다. 아직 `YOUTUBE_API_KEY`가 없어서 정기 AI 분석을 보류 중인 기간의 사용량을 32개 채널 정상 운영 사용량으로 판단하면 안 됩니다.

2026-10-20 요청 영상 `n6nO1MkYId0`(43분 51초)은 기본 화면 확인 간격에서 입력 271,513토큰으로 분당 한도를 초과해 생성 전에 보류했습니다. 사용자가 요청한 이 영상에만 [공식 REST 영상 설정](https://ai.google.dev/api/generate-content#VideoMetadata)의 `fps=0.5`를 적용해 입력 178,148토큰으로 재확인했습니다. 영상 구간을 자르거나 음성을 제거하지 않습니다. 화면을 2초마다 읽으므로 빠르게 지나가는 시각 정보가 누락될 가능성은 있으며 기본 1fps보다 세밀한 영상 검증이 필요한 콘텐츠에 적합한 방식은 아닙니다. 기존 32개 채널의 기본 설정은 변경하지 않았습니다. 입력 설정 변경 시 토큰 계산 캐시도 무효화하고 모든 무료 한도를 다시 검사합니다.
